# Contributing to StangaNet

Thank you for your interest in StangaNet projects.

## Read-only repositories

StangaNet repositories are **personal projects** published for reference and learning purposes.
They are **not open for external contributions**. Pull requests from outside the organization will not be reviewed or merged.

## What you can do

Even though contributions are not accepted, you are welcome to:

- **Open bug reports** using the [Bug Report template](../../issues/new?template=bug_report.yml)
- **Request features** using the [Feature Request template](../../issues/new?template=feature_request.yml)
- **Start a discussion** if the repository has Discussions enabled
- **Fork** the project within the terms of the [LICENSE](./LICENSE)

## What you cannot do

External code contributions (pull requests) are **not accepted**.

Under the Apache License 2.0 you **may**:
- Use the code commercially
- Modify and redistribute it
- Create derivative works

You **must** always retain the copyright notice and include a copy of the Apache License 2.0.

See [LICENSE](./LICENSE) for the full terms.

## Bug reports

When reporting a bug, please include:

- A clear description of the problem
- Steps to reproduce it
- Your environment (OS, runtime version, etc.)
- What you expected vs. what actually happened

## Security issues

Do **not** open public issues for security vulnerabilities.
Follow the process described in [SECURITY.md](./SECURITY.md).

## Code of conduct

All interactions in StangaNet spaces are governed by the [Code of Conduct](./CODE_OF_CONDUCT.md).
